সিদ্ধান্তগুলো পরিষ্কার। এটা **SaaS নয়** — তুমি **হোস্টিং + সফটওয়্যার + ডিজাইন এজেন্সি** চালাবে। নিচের মডেলে plan করো।

---

## তোমার ব্যবসা কী

ক্লায়েন্ট বলে: “আমার স্টোর চালু করে দাও।”  
তুমি দাও: ডোমেইন/হোস্টিং, সাইট সেটআপ, theme, তারপর মাসিক সাপোর্ট।  
Owner শুধু **প্রোডাক্ট, অর্ডার, কাস্টমার** চালায় — ডিজাইন ছুঁয় না।

একটা কোডবেস (`multi-product-ecom`), প্রতি ক্লায়েন্টে **আলাদা সাইট + আলাদা DB**। Theme তুমি বেছে/এডিট করো।

---

## দুই রকম ইউজার (এখন একটাই `admin`)

এখন Themes, Settings, Homepage — সব এক admin দেখে। এটা ভাঙতে হবে।

| | **Super admin (তুমি)** | **Store owner (ক্লায়েন্ট)** |
|--|--|--|
| Login | আলাদা ইমেইল, প্রতি স্টোরেও ঢুকতে পারবে | শুধু নিজের স্টোর |
| Theme | দেখা, অ্যাকটিভ, ডিজাইন এডিট | **মেনুতেই থাকবে না** |
| Homepage / banner / color | তুমি | না (অথবা খুব সীমিত: লোগো, ফোন) |
| Settings: payment, shipping, SEO | তুমি, বা রিকোয়েস্টে | ফোন/ঠিকানা চাইলে দিতে পারো |
| Product, stock, price | সাপোর্টে সাহায্য | **মূল কাজ** |
| Order, status, invoice | দেখতে পারবে | হ্যাঁ |
| Category | শুরুতে তুমি বানিয়ে দিবে | চাইলে পরে দিতে পারো |
| Delete store / dangerous | শুধু তুমি | না |

**Owner panel ছোট রাখো।** বেশি অপশন = ভুল theme/checkout ভেঙে সাপোর্ট বাড়বে।

---

## হোস্টিং তুমি করলে কীভাবে রাখবে

প্রতি স্টোর আলাদা রাখো (boxed-এর মানে এটাই):

- আলাদা cPanel/account **অথবা** এক VPS-এ আলাদা vhost + আলাদা DB  
- আলাদা `uploads/`, আলাদা `.env`  
- আপডেট: একই git tag সব স্টোরে pull — `filesystems`/`.env` স্পর্শ করবে না

**১০ স্টোর পর্যন্ত:** আলাদা cPanel চলবে।  
**১৫+:** এক VPS (Laravel + nginx) সস্তা ও আপডেট সহজ।

তোমার কাছে থাকবে একটা **ক্লায়েন্ট শিট** (শুরুতে Notion/Sheetই যথেষ্ট):

`store name | domain | theme | DB name | owner email | setup date | support expiry | notes`

আলাদা super-admin SaaS অ্যাপ এখন লাগবে না।

## Theme — কয়টা, কী স্টাইল

৫টার বেশি বানাবে না। প্রতিটা **পূর্ণ সাইট** হতে হবে: home, shop, product, cart, checkout, about, contact। এখন `gadget-v1` অসম্পূর্ণ — সেটা আগে শেষ করো, নতুন theme পরে।

| Theme | কার জন্য | টোন |
|--|--|--|
| **Organic / grocery** | খাবার, দৈনন্দিন | সবুজ, নরম — তোমার `organic-v1` |
| **Gadget** | মোবাইল, কভার, ইলেকট্রনিক্স | কালো/ডার্ক, বড় প্রোডাক্ট ছবি |
| **Fashion** | কাপড়, জুতা | বড় হিরো, মিনিমাল কার্ড |
| **General store** | মিক্সড / নতুন ব্যবসা | নিরাপদ, সাদা-গ্রিন |
| **Premium** (পরে) | বেশি দামের ব্র্যান্ড | সরু টাইপ, কম রং |

**নিয়ম:** নতুন নিশ = নতুন repo নয়। একই অ্যাপ + অন্য theme folder + homepage preset।

### Super admin “theme edit” মানে কী

দুই লেয়ার রাখো, নইলে প্রতি ক্লায়েন্টে কোড ঘাঁটবে।

1. **Safe edit (প্রতি স্টোর, অ্যাডমিন থেকে)**  
   লোগো, রং, হিরো স্লাইড, স্ট্যাটস, ব্যানার টেক্সট — এগুলো অলরেডি আছে।
2. **Code edit (শুধু তুমি, লোকাল)**  
   নতুন লেআউট, নতুন theme। Git দিয়ে সব/সিলেক্টেড স্টোরে যাবে।

Owner যেন Themes পেজ + “activate/delete theme” না দেখে। রং/হিরোও চাইলে শুধু super admin-এ রাখো।

## Setup + support — প্যাকেজ

**Setup (একবার)**  
ডোমেইন, SSL, খালি/ডেমো স্টোর, theme, ক্যাটাগরি স্কেলিটন, পেমেন্ট নম্বর, ৩০ মিনিট ট্রেনিং।

**Support (মাসিক)**  
আপডেট, ব্যাকআপ, বাগ, ছোট টেক্সট/ব্যানার চেঞ্জ, অর্ডার ইস্যুতে হেল্প।  
নতুন পেজ/নতুন ফিচার = আলাদা বিল।

উদাহরণ (সংখ্যা তুমি ঠিক করবে):

- Setup: ৮–১৫ হাজার  
- Support: ১.৫–৩ হাজার/মাস  
- নতুন theme বা বড় হোমপেজ: আলাদা  

কন্ট্রাক্টে লেখো: হোস্টিং তোমার; সাইট বন্ধ/মাইগ্রেট করতে চাইলে ফি; সোর্স কোড ক্লায়েন্টের নয়।

## ক্লায়েন্ট অনবোর্ডিং (প্রতি স্টোর)

1. নিশ বাছাও → theme + preset  
2. নতুন DB + সাইট কপি + `.env`  
3. Super admin অ্যাকাউন্ট + owner অ্যাকাউন্ট  
4. লোগো, রং, হিরো, পেমেন্ট, ডেলিভারি জোন  
5. ক্যাটাগরি খালি/ডেমো  
6. Owner-কে শুধু: প্রোডাক্ট অ্যাড, অর্ডার স্ট্যাটাস  
7. Sheet-এ রেকর্ড + সাপোর্ট শুরু তারিখ  

Installer পরে বানাও। প্রথম ৫টা স্টোর চেকলিস্টেই চলবে।

## এখনকার অ্যাপে যা বাকি (প্রায়োরিটি)

**এখনই (ব্যবসা চালু)**  
1. `super_admin` vs `store_owner` — Themes / dangerous settings owner থেকে লুকানো  
2. `gadget-v1` সব পেজ শেষ  
3. ২–৩টা industry preset (ক্যাটাগরি + হোমপেজ টেক্সট)  
4. Deploy/onboarding চেকলিস্ট  
5. Owner-এর জন্য ১ পাতার গাইড  

**পরের মাস**  
6. Fashion theme (যদি কাপড়ের ক্লায়েন্ট আসে)  
7. Backup + আপডেট রুটিন (সব স্টোর একসাথে)  
8. সাপোর্ট ইনবক্স (হোয়াটসঅ্যাপ ঠিক আছে)  

**পরে (১০+ স্টোর)**  
9. ছোট installer  
10. নিজের client sheet → ছোট internal tool  
11. License/domain lock — যাতে কপি সরিয়ে নিয়ে না যায়  

Multi-tenant এক অ্যাপ **এখন দরকার নেই** — তুমি হোস্ট করলেও আলাদা কপিই ঠিক, যতক্ষণ স্টোর ২০-এর নিচে।

## Theme বানানোর নিয়ম (যাতে খরচ না বাড়ে)

- সব theme একই ডেটা ব্যবহার করবে: product, cart, checkout field  
- শুধু Blade/CSS আলাদা  
- Checkout/payment লজিক কমন রাখো — theme-এ ডিজাইন মাত্র  
- নতুন theme = `resources/views/frontend/{slug}/` + `theme.json` + `public/{slug}/`  
- আগে একটা **theme checklist**: home, shop, product, cart, checkout, thank-you, 404, mobile header  

`organic-v1` কে রেফারেন্স ধরো; বাকিরা সেই রুট/কম্পোনেন্ট ফলো করুক।
